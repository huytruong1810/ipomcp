### Findings

- **D1 — No single current-state document.** The real specification is scattered across THEORY (dated sections), L2_CONTRACT, MODEL_SPECIFICATION, the README and BACKLOG.
  - Answering "what does the planner do today, with which defaults, and why?" means reading about 1,000 lines across five files.
  - In the target, one document per bounded context states its current contract. History lives in git.
- **D2 — The README recommends running the default-profile suites.** It shows commands such as `run_benchmarks --suite all` and the `deep_hierarchy_prior` example, while BACKLOG says they are not qualified.
  - Its stated Tiger spec (creak 100%) differs from the L3 study (90%).
- **D3 — Lab-notebook docs belong in an archive, not in `docs/`:**
  - `BENCHMARK.md` and `REVIEW.md`;
  - the 10 protocol docs;
  - the handoffs.

  Their conclusions (which configuration passed which gate, at what n) should be distilled into one results document, keeping links to the archived commit.
- **D4 — Docstrings record history rather than intent.** Examples:
  - "Keep historical default policy seed/metadata identities unchanged" (`config.py`);
  - "one preserves the historical option" (`config.py:56`);
  - "The old capped point prior could…" (`level_convergence_matrix_experiment.py`);
  - "The previous RTS comparison used…" (THEORY).

  The target codebase reads as if built once. Docstrings explain the current design and the reasons for it.
- **D5 — Duplicate statements of the same convention drift.** Tie rules, horizon conventions and creak laws are each described in several places with slightly different wording (Phase 4 T2, Phase 8 B5).

- **A1 — Nothing is backed up outside WSL.** `results/` is git-ignored and is the only copy of 6.5 GB of evidence. Before any deletion or restructure of results, we need a backup location that you choose.
- **A2 — Results paths encode history.** Examples are `bellman-backup-20260924` and `exact-tail-20260924`. The target layout is `results/<study>/<run-id>/` with a manifest. The study name maps to one declared experiment specification (Phase 11), and run ids are timestamps.
- **A3 — Runs that are not interpretable should be marked, not silently kept beside valid ones.** I recommend deleting `payoff_matrix` and `deep_prior` after backup. They will be regenerated by the qualified pipeline anyway.
